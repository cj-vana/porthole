# Porthole for Mac

Native macOS client for Porthole. It receives a streamed Linux desktop over LAN
and renders it with Metal + VideoToolbox. See `../tasks/prd-porthole.md` for
the full PRD.

**Status: PRD story US-004 scaffold.** The app is a dark SwiftUI window whose
Metal-backed surface renders a locally generated, time-derived test pattern at
a selectable, vsync-driven 60/120/144 fps. This proves the render path before
any networking, VideoToolbox, or streaming code exists.

## Requirements

- Xcode (developed against Xcode 26.x, Swift 6.3 toolchain, Swift 5 language mode)
- [XcodeGen](https://github.com/yonaskolb/XcodeGen): `brew install xcodegen`
- Deployment target: macOS 14.0

## Build & run

```sh
xcodegen generate        # regenerates Porthole.xcodeproj from project.yml
xcodebuild -scheme Porthole -configuration Debug build
```

Or open `Porthole.xcodeproj` and press ⌘R. `Porthole.xcodeproj` is a generated
artifact, so edit `project.yml`, never the project file, and re-run
`xcodegen generate` after adding/removing source files.

## What exists

- `Porthole/PortholeApp.swift` holds the `@main` app, a dark, title-bar-hidden window titled "Porthole".
- `Porthole/SessionView.swift` is the session screen, a Metal surface plus minimal
  floating placeholder chrome (becomes the auto-hiding session toolbar later).
  The chrome includes a 60/120/144 fps segmented control, persisted across
  launches via `@AppStorage` and applied live to the surface.
- `Porthole/Rendering/MetalRenderer.swift` wraps `MTKView` as an
  `NSViewRepresentable` with an `MTKViewDelegate`; it applies the selected rate
  to `preferredFramesPerSecond` live, unpaused, so draws are vsync-driven.
- `Porthole/Rendering/Shaders.metal` draws the procedural test pattern: SMPTE-style
  75% color bars with a sweeping luminance gradient, a frame-pacing ticker
  (one cell per frame at the selected rate, one lap per second), and a marker
  block/line traversing the screen every 8 s. All animation is derived from
  monotonic time, so dropped frames appear as stutter in the marker and gaps
  in the ticker.
- `Porthole/Info.plist` includes `NSBonjourServices` (`_porthole._tcp`) and
  `NSLocalNetworkUsageDescription` now, ahead of US-007 discovery.

Rates above 60 fps only become visible on a ProMotion /
high-refresh display. On a 60 Hz panel the display link clamps to 60 fps, and
the ticker shows it: cells then advance at the selected (higher) target rate
while only 60 draws happen per second, so the clamp appears as skipped cells.

## Deliberate decisions

- **App sandbox is OFF.** The client will need raw UDP/TCP sockets (video
  52800/UDP, control 52801/TCP, audio 52802/UDP per the PRD) and GameController
  framework access. Revisit the minimal entitlement set (network client, local
  network, gamepad) before anything ships.
- **Ad hoc signing** (`CODE_SIGN_IDENTITY = "-"`, Sign to Run Locally) so LAN
  dev builds need no developer certificate.
- **`Porthole.xcodeproj` is generated by XcodeGen** from `project.yml`.

- **US-006** adds keyboard/mouse/trackpad capture in the session window.
- **US-007** adds Bonjour discovery of `_porthole._tcp` agents and one-click
