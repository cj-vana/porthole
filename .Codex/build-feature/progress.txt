## 2026-08-25: US-002 hardware encoding (NVENC + VAAPI) done

Implemented real hardware encode of captured frames via an ffmpeg subprocess
per session (stdin rawvideo bgra, stdout Annex B with -aud 1, AUs cut in
Rust). Chose subprocess over ffmpeg-next: box runs FFmpeg n9.0.1 (libavcodec
63), far newer than the crate supports, and subprocess needs no new packages
and survives FFmpeg upgrades. All four backend/codec combos verified at
2560x1440 60fps in/out.

Files changed:
- agent/src/encode/mod.rs: Encoder trait reworked (encode/drain), EncodedFrame
  gains sequence (pts_us dropped until US-003 needs it), create() factory,
  module docs describe the subprocess design.
- agent/src/encode/ffmpeg.rs (new, Linux-only): FfmpegEncoder subprocess,
  NVENC bgra input (GPU convert), VAAPI hwupload+scale_vaapi on
  /dev/dri/by-path/pci-0000:0b:00.0-render, Drop closes stdin then kill.
- agent/src/encode/annexb.rs (new, cross-platform): AUD-based AU splitter +
  IDR detection for h264/hevc, unit tests run on macOS.
- agent/src/main.rs: capture thread feeds encoder paced at --fps
  (accumulating-deadline pacing, see Patterns), merged 1s capture+encode
  stats line, PORTHOLE_DUMP_VIDEO debug dump hook, --keyframe-interval-secs.
- agent/src/config.rs: keyframe_interval_secs option (default 2).
- agent/README.md: encoder architecture section, new flag, current state.

Verification (on the box): NVENC run shows nvidia-smi utilization.encoder
13-16% with enc_in/enc_out 60/60 at 2560x1440, agent ~9% CPU, ffmpeg ~14%.
VAAPI run: NVENC 0%, ffmpeg on the AMD by-path node, 60/60 fps. ffprobe on
PORTHOLE_DUMP_VIDEO output confirms valid h264 2560x1440 for both backends.
hevc works on both backends. Known gaps: request_keyframe is a no-op for the
subprocess (FR-4 deferred to US-003); NVENC output kbps on the static desktop
is far below 40M (VBR, nothing to encode), VAAPI fills the CBR target.

Learnings for future iterations:
- nvidia-smi field for encoder load: utilization.encoder (NOT
  encoder_utilization.session). Sample while agent runs, process exits fast.
- ps -C <comm> -o %cpu= for process CPU; %cpu is lifetime average, sample
  mid-run.
- ffmpeg on Arch is VERY new (n9.0.1); check crate bindings version ceilings
  before choosing linking over subprocess.
- h264_vaapi rate control fills the CBR -b:v target even for static content;
  nvenc defaults to VBR-ish and drops to near zero kbps on static images.
  Neither is a bug.
